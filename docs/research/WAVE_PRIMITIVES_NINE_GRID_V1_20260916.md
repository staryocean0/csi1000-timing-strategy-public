# 单波基础工具与九宫格组合 V1

## 定位：先有单波，再有组合

本次按用户的新任务拆成两个可复用对象，不再把“两波共识三分类”当成唯一产品。

1. **单波工具**：在指定K线视图和因果成熟规则下，识别、记录并完整画出每个已确认的 `L0-H0-L1` A-wave。
2. **组合工具**：把严格相邻两波的内部方向组成 `3×3=9` 个有序格子，保留连续斜率、位移和加快/放慢信息。

它们是 Layer2 形态研究基础设施，不是买卖信号。C—G 原有文件、固定参数、回执和裁定不修改；旧共识分类保留为比较字段。新增工具不是对旧研究的事后改写。

## 一、哪些已经有证据，哪些还没有

既有实现与证据是 V0800-C 的 `MIN_LEG=4`、`MAX_UNFINISHED_LEG=48` 因果回放，以及随后固定5分钟视图上的 D—G 研究。

**不能把它扩写成“任意K线级别、任意目标频率均已验证”。** 新增 API 支持传入其他已审计视图和探测参数，但非基准设置还需重新核验。当前提交是 source-only 工具和诊断协议；未执行真实多频率扫描、未认定天然频率簇、未自动选择波段级别。

此前展示的六个案例是有限示例，不是对整个新单波/九宫格产品的完整验收。后续正例、弃权例、边界例和不合尺度例必须采用同等级完整原始OHLC证据。

## 二、单波如何定义

沿用现有**收盘价选择拐点时刻**的因果状态机：候选极值允许更新；反向候选极值的发生位置与原候选相隔至少 `min_leg_bars`，才确认原极值。确认事件只追加，不向历史回填“当时已知”。超出未完成腿的上限就 reset，建立新 epoch；初始左截断拐点不参与构造完整波。

相邻的低—高—低确认点形成一个 A-wave。波的起点、顶点、终点、确认时间分别记录。**拐点发生位置来自 close；画通道时使用该位置K线的 low/high。** 因而邻近另一根K线可能有更长的影线，不能把本定义宣称为逐影线局部极值识别。

强单边、全平、尚未确认或跨 reset 的走势，不因目标周期到了就强造完整波。

### 三组配置必须分开

| 配置 | 含义 | 与其他配置的区别 |
|---|---|---|
| `BarView` | 标的、K线级别、每根名义交易分钟、来源身份、收盘时间戳 | 改标签不等于生成另一级K线；必须提供对应视图，不本地默默重采样 |
| `min_leg_bars / max_unfinished_leg_bars` | 拐点反向成熟间隔与未完成腿的reset上限 | 改它们会改变抽取到的波；不是“目标周期”本身 |
| `target_period_bars` 与两个容许因子 | 希望查看的完整低到低周期及其下界/上界 | 只标记已抽取波是否入带，不强造波，也不跳过中间波重新拼接 |

设中心周期为 `N` 根，频率是 `1/N` 周/根。周期容许带为：

`ceil(N / period_lower_factor) <= duration <= floor(N * period_upper_factor)`。

默认上下因子均为 `sqrt(2)`，来自旧尺度带表达方式，只是明确的初始配置，不是新的最优频率结论。也可显式设置不对称因子。例如 `N=24` 时默认带为 `[17,33]` 根；在5分钟视图中名义周期为120交易分钟，在15分钟视图中为360交易分钟，二者不是同一个实际时间尺度。

这里的“左右”是**周期容许范围的两侧**，不是拐点两侧的居中未来窗口。拐点确认延迟由成熟规则决定，不能拿未来K线去回填确认时间。

### 一个波保留哪些量

- 三个结构点的原始价格、bar索引、时间；确认时间、延迟、最早可消费bar；epoch与稳定的波身份。
- 完整周期根数、`1/N` 频率、名义交易分钟、实际日历跨度。休市和缺口不被混称成相同的交易时间。
- 底线原始对数斜率 `s=(log(L1)-log(L0))/N`、通道高度 `h`、归一化位移 `g=s*N/h`。
- 内部 `UP/RANGE/DOWN`、是否在目标周期带内。内部描述不等于对外市场状态。

## 三、九种组合：先完整保留，再谈用途

沿用 `tau=0.20`：`abs(g)<=tau` 为 RANGE，正向越界为 UP，负向越界为 DOWN。这里的“横”是相对波高的微小迁移区，**不是斜率必须恰好为零**。

| 前波 → 后波 | DOWN | RANGE | UP |
|---|---|---|---|
| DOWN | 下移→下移 | 下移→趋平 | 下移→上移 |
| RANGE | 趋平→下移 | 趋平→趋平 | 趋平→上移 |
| UP | 上移→下移 | 上移→趋平 | 上移→上移 |

这些是中性结构描述。`UP__DOWN` 可表现为先抬高再回落，`DOWN__UP` 可表现为先下移再抬高；仅凭该代码，不把它们宣布成已确认市场顶部、底部或未来反转。

组合必须是同一 epoch、共享相同低点发生位置与价格的**真正连续**两波。先构造完整严格事件流，再标记同尺度和目标带资格。不能先筛选波，再把中间缺了波的两个对象拼成连续结构。

每个有效严格pair保存 `primitive_pair_code`。不合尺度或不在目标带时，`qualified_pair_code=null` 并保留原因；不是增造“第十种方向”，也不是丢掉证据。九格计数与未通过资格的数量必须闭合到全部严格pair。

### 加快/放慢是附加轴，不应被 Uncertain 吞掉

同向非RANGE的格子再记录 `raw_speed_relation=faster/equal/slower`，由前后**实际每bar斜率的绝对值**比较。并同时保存连续比值和有符号差值，而不是只有一个结论。

`g` 是归一化整波位移，不是每bar原始斜率。两波高度不同，即使 `g` 变大，实际斜率也可能变小。因此旧 `max(|g1|,|g2|)/min(|g1|,|g2|)` 不能直接叫物理速度比，而且它不保留加快/减慢的时间顺序。本工具分别保存 `|s_current|/|s_previous|` 与 `|g_current|/|g_previous|`，零分母输出 null。

`legacy_consensus_state` 仍可为 Uncertain，但不再删除 `UP__UP` 或任意其他基础组合。数值近似相等的浮点容差不是新增的科学稳定趋势阈值。九格的bar-time持有/失效机制本次没有授权，不能自动套用 G 的三种decisive carrier。

## 四、频率聚集：检验对象，不是预设结论

新增 `scan_periods` 先在同一输入视图上做显式探测设置比较，统计**未经目标周期、同尺度或两波分类筛选的全部已确认单波**。初始诊断设置为 `(2,24)、(4,48)、(8,96)、(16,192)`，中间 `(4,48)` 为旧基准。此清单是待执行方案，不代表哪一档通过验收。

必须分别展示各K线级别、探测设置、确认年份的完整波长分布；记录reset、终端未确认对象和区间外数量。同一设置只跑一次，换了目标容许带不能变成新的独立证据。同源同视图的相同三点结构在联合统计中去重；不同但重叠的结构仍不声称独立样本。

周期直方图同时给出计数、占全部波的比例、每单位 `log2(period)` 的密度，避免把更宽区间容纳更多波误当成聚集。内部严格密度峰只叫候选；边缘峰、平顶、不稳定峰不能自动变成天然级别。

自然聚集的正式裁定还必须检查：跨年稳定、成熟和reset窗口敏感性、分箱起点/宽度敏感性、未确认与reset造成的截断、重叠结构、预注册的无聚集对照，以及完整OHLC视觉核验。无聚集对照的统计模型还需在真实执行前另行冻结；本提交不提供伪造的显著性检验或p值。

**允许最终发现没有稳健天然分界。** 此时保留连续尺度，不强行选“大中小”三个簇；不因某档未来收益更好来选频率。

实现参考：NumPy `histogram` 关于不等宽分箱与密度的官方说明，https://numpy.org/doc/stable/reference/generated/numpy.histogram.html 。这里只借用计数/密度定义，不借此声称市场存在周期。

## 五、调用方式

在仓库根目录、使用已安装的公开依赖：

```python
import sys
sys.path.insert(0, 'executor')
from two_wave_toolkit_v1 import BarView, WaveConfig, build_inventory
from two_wave_toolkit_diagnostics_v1 import scan_periods
from two_wave_toolkit_visuals_v1 import render_wave_svg

# bars由受控DataHub/runner提供；有timestamp/open/high/low/close列。
# 不用这一API从任意位置读取私有文件，也不绕过标准执行入口。
view = BarView('000852.SH', '5m_offset_0', 5, 'sha256:<verified-input-hash>')
config = WaveConfig(target_period_bars=24)
inventory = build_inventory(bars, view, config)
# inventory['waves']保留全部波，within_target_band用于选择展示。
# inventory['strict_pairs']保留完整严格pair及其九格、资格和旧分类。
selected = [w for w in inventory['waves'] if w['within_target_band']]
svg = render_wave_svg(bars, view, config, selected[0]) if selected else None
settings = [WaveConfig(min_leg_bars=k, max_unfinished_leg_bars=12*k) for k in (2,4,8,16)]
diagnostic = scan_periods(bars, view, settings)
```

SVG画完整OHLC蜡烛，不拿几个点代替；绘图区从起点到确认bar截止，说明下一根才可消费，但不展示之后行情。图形是单波归因视图，不是宣称所有中间bar都具有该方向。

## 六、交付与执行边界

本次新增三个API文件、协议JSON、本说明和合成合同测试。旧profile、broker、controller及私库文件不改；不新建真实研究run。

真实扫描必须另行把source commit、原生视图身份、时钟、资源、独立verifier、输出白名单及受控回存规则绑定到标准 `public-compute.yml / workflow_dispatch`。现阶段唯一已知可复用的真实基准输入是已消费的2015—2020、70114根5分钟数据；其他级别尚未获准入，2026不读。执行前不把 `real_market_scan_executed` 改成 true。

验收顺序：代码合同与旧基准兼容 → 原生视图身份 → 标准真实扫描及独立复核 → 单波多尺度完整图形验收 → 聚集裁定 → 九格分布与完整案例。后续收益/交易用途留待另外任务。
